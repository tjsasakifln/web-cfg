### 3.2 Visitor journeys (validated)

See `docs/uiux-visitor-redesign/VISITOR-JOURNEYS.md`:

1. **Contrato sob pressão** → form `jornada=contrato`  
2. **Orientação** → hub problem search / stages  
3. **Checklist aditivo** → 4-step progressive tool  
4. **Resposta jurídica** → article answer box + single CTA  

### 3.3 Conversion form UX

- Multi-step: Step 1 required (nome + WhatsApp/email + tipo); Step 2 optional  
- Endpoint: `POST /.netlify/functions/lead`  
- Confirmations differentiated by journey  
- Upload of documents: **not** in form — WhatsApp secure handoff on thank-you

## 4. Component inventory (de facto)

No React component library. Patterns are **CSS classes + HTML partials** generated by Python/shell patches.

| Pattern | Classes / markers | Use |
|---------|-------------------|-----|
| Sections | `section`, `section--tight/default/loose` | Vertical rhythm |
| Hero split | `hero_split` archetype | Home thesis |
| Tension sequence | multi-block erosion | Home |
| Journey rail | table desktop / cards mobile | Macro phases |
| Buttons | `button-primary`, secondary styles | CTA hierarchy |
| Form controls | native + custom steps | Lead funnel |
| Hub search | `data-hub-search` | Content discovery |
| Answer box | editorial article pattern | Direct answer |
| Tool chrome | `styles-tools.css` + tools-common | Progressive tools |
| Contact float | `contact-float` aside | WhatsApp (≥620px) |
| Nav | brand.json driven | Header menu |

**Card policy:** allowed only for independent actions / real comparison / reusable units — not default list structure (design system gates).

## 11. Débitos UX/UI identificados

| ID | Débito | Severidade | Impacto UX | Esforço |
|----|--------|------------|------------|---------|
| UX-01 | Dual CSS surfaces (global vs tools) without shared primitive package | Médio | Inconsistência long-term | M |

| UX-03 | Hub/editorial residual taxonomy language (actively remediated on branch) | Médio | Clarity | S–M |
| UX-04 | Form contingency/JS messaging historically leaked (fixed pattern — watch) | Médio | Trust | S |
| UX-05 | Checklist previously wall-of-items (progressive rebuild — validate all states) | Médio | Completion rate | S |
| UX-06 | Multiple offer pages must keep distinct section rhythm (gate-enforced) | Médio | Differentiation | S ongoing |
| UX-07 | No storybook/component playground — review by full HTML only | Médio | Design QA cost | M |
| UX-08 | Contact float desktop-only may hide WhatsApp for some mobile users relying on float | Baixo | Reach | S |
| UX-09 | Tool UI split across inline scripts + shared JS | Médio | Maintainability | M |
| UX-10 | Thank-you pages still simpler than main design system depth | Baixo | Continuity | S |

## 13. Frontend tech constraints (for implementers)

- **No SPA router** — multi-page; keep progressive enhancement  
- Prefer editing **sources** (`data/*`, templates, root shells) not only `_site`  
- Run `test:design`, `test:copy`, `test:ui`, `test:visitor-redesign` before merge  
- CTA counts and section archetypes are **hard gates**, not suggestions
