# Créditos de exportação — operação e homologação

O Netcup opera a carteira de exportação com Firebase Auth e Firestore dedicados. A configuração padrão é `off`. A memória JSON do Modela Pro é produzida pelo servidor. Para resultados gerados no navegador, o servidor autoriza a entrega e devolve um comprovante vinculado ao formato e ao hash do resultado. Cálculos, projetos editáveis e amostras continuam disponíveis nas ferramentas. Consulte [a decisão de arquitetura](../architecture/ADR-TOOLS-001-export-entitlements.md).

## Ensaio local

Node 22, Java 21 e Firebase CLI. A instalação usa o lock do site e o lock privado do Admin SDK. O modo demo usa Auth e Firestore no loopback e não usa credenciais ou recursos do Google Cloud.

```bash
npm ci --engine-strict
npm ci --omit=dev --ignore-scripts --no-bin-links --prefix runtime/tools-commerce/deps
npm run build:firebase-auth
npm run test:tools-commerce
npx --yes firebase-tools@15.35.0 --config firebase.tools-commerce.json --project demo-confenge-tools emulators:exec --only auth,firestore "node --test tests/tools-commerce/firestore-emulator.test.cjs"
```

Para desenvolvimento, aponte o runtime Node para `TOOLS_COMMERCE_MODE=emulator`, `TOOLS_COMMERCE_FIREBASE_PROJECT=demo-confenge-tools`, `FIREBASE_AUTH_EMULATOR_HOST=127.0.0.1:9099`, `FIRESTORE_EMULATOR_HOST=127.0.0.1:8085` e um `TOOLS_COMMERCE_HMAC_KEY` de ensaio. Sirva o site e faça proxy de `/api/web/tool-credits*` na mesma origem local. Somente o servidor de ensaio libera `http://127.0.0.1:9099` no CSP. Os testes exercitam Auth e transações reais nos emuladores, com HTTP do Mercado Pago simulado.

## Homologação na estação de trabalho

Execute `npm run build:site` para montar `_site`. Use um arquivo de ambiente privado, fora do repositório, para configurar o Firebase institucional de homologação, ADC, HMAC e a lista `TOOLS_COMMERCE_SANDBOX_UIDS`. Cadastre e confirme no Firebase Auth os dois usuários usados para testar a indicação. Use seus UIDs na lista. Configure `TOOLS_COMMERCE_MODE=sandbox` e `TOOLS_COMMERCE_SANDBOX_ORIGIN=http://127.0.0.1:8790`. Comece com `TOOLS_COMMERCE_PURCHASES=0` para validar o cadastro e a emissão gratuita.

Use um projeto Firebase com ID terminado em `-hml` para homologação e outro com ID terminado em `-prod` para produção. Configure `TOOLS_COMMERCE_MP_LIVE_SELLER_ID` no ambiente de produção com o ID da conta vendedora contratada. O registro de cada pedido guarda a versão e o hash da seção de créditos dos termos. Atualize ambos se o conteúdo dessa seção mudar.

```bash
node --env-file=/caminho/privado/creditos-hml.env scripts/tools-commerce/serve-hml.mjs --port 8790
```

Abra `http://127.0.0.1:8790/ferramentas/`. O servidor local lê os arquivos de `_site` e encaminha as duas APIs de créditos ao runtime. Configure o Access Token da aba **Teste** e o User ID da conta vendedora de teste em `TOOLS_COMMERCE_MP_TEST_SELLER_ID`. Para testar a compra, configure `TOOLS_COMMERCE_TERMS_APPROVED=ferramentas-creditos-v2`, `TOOLS_COMMERCE_PURCHASES=1`, `TOOLS_COMMERCE_SHARED_EXPORTS=1` e `TOOLS_COMMERCE_MP_CHECKOUT=1`. Reinicie o processo. Faça uma exportação de cortesia e uma paga em ferramentas distintas. A entrega da notificação do Mercado Pago exige uma instância de homologação com URL HTTPS própria e o segredo do webhook de teste.

## Projetos e contas reais

1. **Firebase:** entrar no [console](https://console.firebase.google.com/) com a conta institucional da CONFENGE. Criar projetos exclusivos e separados para homologação e produção; confirmar responsável, plano e localização do Firestore antes de provisionar. Não aplicar as regras de negação geral a um projeto compartilhado. Registrar um app web em cada projeto. Habilitar [e-mail e senha](https://firebase.google.com/docs/auth/web/password-auth), confirmar domínios autorizados e testar e-mails de verificação e recuperação. Não habilitar login anônimo. Confirmar limites de e-mail e proteção contra enumeração de contas. Implantar `firebase deploy --only firestore:rules --config firebase.tools-commerce.json --project <projeto-exato>` a partir da conta de operação e verificar negação de leitura e escrita direta. Veja [Rules e IAM](https://firebase.google.com/docs/firestore/security/iam).
2. **Acesso do runtime:** dar à identidade de serviço apenas as permissões de operação no banco e de consulta de usuário/revogação no projeto dedicado; papéis de referência `roles/datastore.user` e `roles/firebaseauth.viewer`. Preferir credencial ADC federada se disponível. Caso seja usada uma chave, instalá-la fora do release sob `/etc/confenge-web/` com proprietário root, grupo do serviço, modo `0640`; apontar `GOOGLE_APPLICATION_CREDENTIALS` nesse diretório. Configurar projeto, app ID e API key web pública em `/etc/confenge-web/runtime.env`. Guardar a chave HMAC aleatória (32 bytes em base64url) e preservar backup. Trocar essa chave sem uma migração controlada invalida a associação de e-mail e a recuperação de emissões anteriores.
3. **Mercado Pago.** Em [Suas integrações](https://www.mercadopago.com.br/developers/panel/app), crie a aplicação CONFENGE Ferramentas para pagamentos on-line com [Checkout Transparente / Orders, Pix](https://www.mercadopago.com.br/developers/pt/docs/checkout-api-orders/payment-integration/websites/pix). Em homologação, use o token da aba **Teste**. O runtime confere o perfil do vendedor antes de criar uma ordem, pois o prefixo do token pode ser igual nos dois ambientes. A [compra de teste](https://www.mercadopago.com.br/developers/pt/docs/checkout-api-orders/integration-test/pix) usa `payer.first_name=APRO` e o e-mail de exemplo do provedor por padrão. `TOOLS_COMMERCE_MP_TEST_BUYER` permite usar um endereço `@testuser.com`. Guarde token e segredo de webhook em ambiente privado e em valores distintos por ambiente. Configure [notificações de Order](https://www.mercadopago.com.br/developers/pt/docs/checkout-api-orders/notifications) na URL HTTPS de homologação em `/api/web/tool-credits-webhook`. Em produção, a URL é `https://confenge.com.br/api/web/tool-credits-webhook`. A autorização de saldo exige `GET /v1/orders/{id}` do próprio vendedor, status acreditado e valores integrais.
4. **Sandbox externo.** Execute o runtime fora do perfil `netcup-production`, com `TOOLS_COMMERCE_MODE=sandbox`, `TOOLS_COMMERCE_SANDBOX_ORIGIN` e `TOOLS_COMMERCE_SANDBOX_UIDS`. Use o app, o banco e o token de teste. Registre evidência de QR, confirmação integral, recebimento da notificação assinada, débito, duplicata, estorno, atendimento e recuperação. O ensaio com emuladores cobre o fluxo com respostas simuladas.
5. **Ativação.** Validar no Netcup todas as rotas de resultado, Pix e Checkout Pro em homologação, o webhook assinado de Orders, conciliação, termos v2, tarifas e atendimento. Excluir API, comprovantes e QR de cache e de analytics. Configurar `TOOLS_COMMERCE_MODE=live`, `TOOLS_COMMERCE_TERMS_APPROVED=ferramentas-creditos-v2`, `TOOLS_COMMERCE_SHARED_EXPORTS=1` e `TOOLS_COMMERCE_MP_CHECKOUT=1`. Ligar `TOOLS_COMMERCE_PURCHASES=1` após conferir a versão exata do release e os segredos. A saída do checkout indica onde consultar o pedido. O saldo só é atualizado após consulta autenticada ao Mercado Pago. Validar o [contrato de Checkout Pro via Orders](https://www.mercadopago.com.br/developers/pt/docs/checkout-pro-orders/create-order?scope=prod).

### Login federado

Configure os [provedores OAuth do Firebase](https://firebase.google.com/docs/auth/configure-oauth-rest-api) no projeto do ambiente. Use `https://<projeto>.firebaseapp.com/__/auth/handler` como URL de retorno no painel de cada provedor e autorize o domínio do site no Firebase. Confira se o provedor inicia o fluxo OAuth antes de publicar seu botão.

No ambiente privado do runtime, `TOOLS_COMMERCE_AUTH_PROVIDERS` recebe os IDs confirmados, separados por vírgula. O valor inicial para Google é `google.com`. Os demais IDs são `linkedin.com`, `apple.com`, `facebook.com`, `github.com`, `microsoft.com`, `twitter.com` e `yahoo.com`. Guarde as credenciais OAuth na configuração do Firebase. O saldo continua associado ao UID autenticado e exige e-mail verificado. Em páginas com isolamento para processamento BIM, o acesso social abre a carteira central em outra aba.

## Incidentes e métricas

- `TOOLS_COMMERCE_PURCHASES=0` impede novas compras. `TOOLS_COMMERCE_EXPORTS_PAUSED=1` suspende as emissões autorizadas e novas compras. Pedidos existentes continuam a ser conciliados. Preserve o Firestore e mantenha uma versão do webhook capaz de consultar os dois tipos de pedido até encerrar os pendentes.
- `review` sinaliza criação incerta, divergência no pagamento, devolução parcial ou disputa. A API recupera pedidos de criação incerta pela referência. `node runtime/tools-commerce/ops.cjs reconcile ORD…` mostra o fato verificado. Use `--apply` para conciliar de forma idempotente. Para uma disputa resolvida a favor do vendedor, confirme o crédito integral no extrato antes de executar `node runtime/tools-commerce/ops.cjs resolve-dispute ORD… --seller-credit-confirmed`. O comando libera somente a retenção daquele pedido. Estornos são operados no Mercado Pago. Se o crédito ou a cortesia já tiver sido usado, revise a conta e preserve o histórico. Registre correções de saldo como lançamentos compensatórios com autorização e referência.
- `node runtime/tools-commerce/ops.cjs usage 2026-11-01 2026-12-01` retorna contagens agregadas com datas civis em `America/Sao_Paulo` (data final exclusiva; até 31 dias): contas, emissões grátis/cortesia/pagas, pedidos confirmados e reversões por pacote. `referralCohort` inclui somente as contas indicadas criadas dentro do intervalo e mostra o estado delas no momento da consulta. `referralEvents` conta recompensas ganhas e revertidas pelo instante do lançamento, inclusive quando a conta indicada pertence a uma coorte anterior. Não dividir esses dois conjuntos como se compartilhassem o mesmo denominador. Para não depender de índice manual de `collectionGroup`, a operação seleciona por índices automáticos somente contas com recompensa ativa ou revertida e consulta seus ledgers em lotes com no máximo 20 consultas concorrentes; qualquer erro de leitura interrompe o relatório, sem substituir dados por zero. Esse custo é `O(convidadores históricos)` e é adequado ao piloto; um agregado global versionado é melhoria explícita antes de escala alta. Receita bruta é a soma original confirmada, sem dedução de tarifa, reversões ou tributos. Conferir financeiro no Mercado Pago e seguir o processo de faturamento em Warmbly. O arquivo da emissão e a planilha não ficam no ledger.
- Uma conta verificada ganha um crédito inicial; uma indicação ganha **uma** cortesia após a primeira emissão com crédito comprado. O teto é dez por mês em São Paulo. Cliques e publicações não geram crédito. Compartilhamento voluntário usa o link do visitante e deixa o resultado privado. Para futuras campanhas, manter a divulgação da cortesia, sem incentivar curtidas ou automação. Veja as [políticas do LinkedIn](https://www.linkedin.com/legal/professional-community-policies). Medir indicados por conta, conversão em uso pago, cortesia consumida, estornos e margem antes de ampliar; crescimento é hipótese, não projeção garantida.

Para integrar uma ferramenta, registre os formatos em `runtime/tools-commerce/exports.cjs` e vincule cada ação de entrega a `exportToolResult`. Gere o resultado antes da autorização. Se a resposta for interrompida, retome a tentativa na página para recuperar o comprovante com a mesma referência. Teste a paridade dos arquivos e o débito único. O comprovante registra o hash informado pelo navegador para aquela emissão e permite conferência do arquivo local. Ele não certifica o cálculo nem limita a cópia de dados já visíveis ao visitante.
